# Interview Questions You'll Be Able to Answer

> If you genuinely understand every decision in your project, you'll be able to confidently answer questions like:

**Backend**
- How does an HTTP redirect work?
- What's the difference between 301 and 302?
- How do you validate user input?
- How do you structure a scalable Node.js application?
- Why use middleware?

**Database**
- Why did you choose MongoDB?
- What indexes did you create and why?
- What happens without an index?
- How does a TTL index work?
- How would you model analytics data?

**Caching**
- Why Redis?
- What is the Cache-Aside pattern?
- What happens on a cache miss?
- How do you keep cache and database consistent?\

**Scalability**
- How would your service handle 100 million URLs?
- Where are the bottlenecks?
- How would you scale horizontally?
- When would you shard the database?
- How would you design for high availability?

**Reliability**
- What happens if Redis fails?
- What happens if MongoDB is temporarily unavailable?
- How would you make the system fault tolerant?

**Security**
- How do you prevent abuse?
- How do you handle malicious URLs?
- How would you implement rate limiting?

**Architecture**
- Why did you organize the project this way?
- How would you split it into microservices in the future?
- What trade-offs did you make, and why?
